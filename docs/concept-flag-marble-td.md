## 0. 一句话

古代战争的**将军与传令官**：不同旗语指令让部队切换不同阵型，阵型决定胜负。把这个内核做成「弹珠物理 + 同色合成 + 塔防 + 关卡倒计时」的四层玩法。

---

## 1. 原始构想（用户原话拆解）

> 玩法来源于古代战争里面的将军或者传令官，不同的旗语就会转换不同阵型，对战争胜负有着关键作用。
> 玩法：下边弹珠 / 上边塔防，七龙珠合成，有不同颜色，组合合成生成不同效果，塔防角色可以根据不同的组合，产生不同的效果，或者生成不同种类的小兵，关卡需要倒计时。

拆成四层：

| 层 | 内容 | 作用 |
|---|---|---|
| 底层 | 弹珠（弹球物理） | 手感与视觉主体 |
| 中层 | 多颜色弹珠**同色合成**，不同组合生成不同效果 | 成长线 |
| 上层 | 塔防：塔防角色依据合成出的颜色/组合产生不同效果，或生成不同种类小兵 | 消费与结算 |
| 策略层 | **旗语 → 阵型切换** | 灵魂机制，差异化点 |
| 约束 | 每关倒计时 | 压力源 |

## 2. 三件不能拖的事

### 2.1 「七龙珠合成」这个说法必须换掉

- **七龙珠是注册商标**，聚光灯报名材料里出现该词有合规风险；且会把作品推向「同人」观感，评审一眼看出是抄。
- 机制本身没问题，要保留的只是「**同色两个碰在一起升级**」这条规则。
- 建议命名：**同色共鸣** / **共鸣合成**（或任意中性名）。
- 同理：题材用旗语没问题（属公有领域的历史军事概念），但**不要用具体历史战役名、不要用真实将军名**。

### 2.2 量级评估：这是 D1「末日小铺」的三倍工作量

| 系统 | 难度 | 单独做完预估 |
|---|---|---|
| 弹珠物理 | 中（手感调试是无底洞） | 3–5 天 |
| 多色多阶合成 | 中 | 2–3 天 |
| 塔防（路径 / 波次 / 敌人） | 中 | 3–4 天 |
| 旗语阵型系统 | 中高（要设计 + 要 UI） | 3–5 天 |
| 倒计时关卡 | 低 | 1 天 |
| **合计** | | **12–18 天** |

**时间账：** 21 天 GameJam 减去合规、美术、试玩人数、开发者日志，**可用开发时间约 14–16 天**。刚好卡在能做完的边缘，**没有任何容错空间**。

→ **必须砍掉一层。**

**砍塔防的复杂度，不砍核心体验。** 建议把「敌人走路径 + 炮台打敌人」改成：
> **弹珠本身就是防线** —— 弹珠在槽内物理滚动，同色相撞合并，合成后的弹珠滚到防线位置阻挡敌人。

这样「弹珠物理 + 合成」天然就是塔防，砍掉的是**炮台系统**（寻路、射程、攻速、目标选择四个子系统），而不是核心手感。

### 2.3 旗语阵型作用在哪，必须二选一

当前存在两个互不相干的可能实现：

| 方案 | 旗语改变什么 | 特点 |
|---|---|---|
| **A. 阵型 = 弹珠发射器排列** | 旗语改变发射器的角度 / 位置 / 朝向 → 影响弹珠怎么滚、往哪滚 | **更贴合「传令官展旗」意象，因果清晰、有手感**（旗一展、轨迹当场变） |
| **B. 阵型 = 合成规则 / 塔防单位配置** | 旗语改变「什么颜色能合成什么」「小兵往哪打」 | 更好实现，但更抽象，玩家不易理解 |

→ **倾向 A**，但需最终拍板，因为它决定整个 flag 系统的实现方式。

## 3. 旗语机制的设计要点

旗语是本设计的差异化点，值得单独设计。

### 3.1 旗语必须稀缺

若旗语能随便发，它就退化成一个加速按钮，不是决策。
需要一个稀缺资源约束，例如**令旗存量**或**旗语冷却**；且该稀缺资源最好**本身参与合成体系**，这样它与其他系统咬合，而不是孤立开关。

### 3.2 每面旗 = 一个阵型 = 一组可预测的效果

古代军队阵型有讲究，可直接映射为 4–5 面旗，每面旗改变**一件明确的事**。
❌ 不要做成「每面旗 +5% 全属性」那种糊弄式增益。

### 3.3 旗语要与倒计时咬合（最关键的一点）

> **旗语可以「换时间」：多花 10 秒，换一个强力阵型持续 20 秒。**

这样一来，倒计时压力与旗语决策变成**同一份资源的两面**——你把「时间」变成了唯一货币。

⚠️ **重要发现：这与旧方向 D1「末日小铺」的核心是同一个内核。**
D1 = 天数 = 唯一硬货币 + 不可逆 + 结局定格（纯数值版）；
本构想 = 时间 = 唯一硬货币 + 不可逆（换阵型要花时间）（动作版）。
→ **换方向不等于从零开始，内核可复用，`balance_sim.py` 的诊断框架也能复用。**

## 4. 旗语可考的历史素材（供设计取用）

- **旗的分类**：阵图旗（金鼓旌旗，标示阵形）、将旗（主将方位所在）、认旗（识别友军、防止误伤）
- **经典阵型**：
  | 阵型 | 特征 | 可映射的游戏效果 |
  |---|---|---|
  | 锋矢阵 | 前锋锥形突击一点 | 单方向高倍伤害 / 穿透 |
  | 雁行阵 | 左右张翼展开 | 扇形覆盖 / 多方向 |
  | 环形阵 | 防御包围 | 全向护盾 / 阻挡强化 |
  | 鱼鳞阵 | 中央厚、两侧薄 | 中心加成、边缘递减 |
  | 车轮阵 | 两翼交替冲击 | 轮换生效 / 时间分段 |
- **信号约定（极佳的机制灵感）**：
  - **击鼓为进、鸣金为退** —— 中国军队近乎通用的信号语义
  - 关键点：**同一个动作（敲击）有进/退两种含义，取决于是谁敲的**。这本身就是「有限指令集 + 上下文决定效果」的设计原型，可直接做成「同一面旗，在不同状态下语义相反」。

## 5. 待验证问题（等竞品研究回来逐条回答）

研究任务已派出，覆盖 6 块：① 弹珠物理类（含 TapTap《幸运弹球》9.0 分）② 同色合成 merge 机制 ③ **合成 + 塔防的缝合方式**（重点）④ **阵型切换 / 有限指令集的战术游戏**（最关键）⑤ 倒计时机制在放置/塔防里的用法 ⑥ 组合空白分析。

需要研究回答的具体问题：

1. 把弹珠当**防御手段**（而非发射/消除）有没有成熟先例？
2. 「合成结果决定塔防单位类型」有哪些真实作品？它们怎么缝合的、为什么成功或失败？
3. 「战斗中用有限指令切换部队阵型」最接近的代表作是谁？Squad 语音指令 / Bad North 实时暂停调度 / 三国志战略版阵型切换 哪个更值得借鉴？
4. **有没有游戏把「旗帜/信号」做成显式核心机制**（而非装饰）？
5. 有没有任何一款游戏同时具备「弹珠物理 + 合成 + 塔防 + 阵型切换」四项？最接近的三款各差在哪？
6. 倒计时 + 放置怎么才不让玩家挫败？

## 6. 21 天可行性初判（待研究修正）

| 保留项 | 状态 |
|---|---|
| 弹珠物理（当防线） | 必留，但需限制为单槽/双槽，简化物理 |
| 同色合成（3 色 × 3 阶 = 9 种成品） | 必留，是成长线主干 |
| 旗语阵型（4 面旗） | **灵魂，必留** |
| 倒计时 | 必留，是旗语的成本来源 |
| 传统塔防炮台系统 | **建议砍掉** |
| 多关卡 | 建议只做 1 张地图 + 3 关难度变化（主题 10/1 公布后对齐） |

**风险**：
- 弹珠手感调试容易吃掉 3 天以上 → 建议第 1 周就做出「能滚能合」的最小切片，先锁手感
- 四系统叠加导致每个都做不深 → 宁可 3 阶 3 色，不要 5 阶 5 色
- 倒计时压力 + 合成操作会互相打断 → 需要实测调参
