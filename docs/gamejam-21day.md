## 5+ 篇开发者日志排期

要求是"开发期发 5 篇以上"，建议做 **7 篇**留余量。每篇结构固定：

```
1. 今天要解决什么（具体到一个问题，不是一个模块）
2. 试过什么方案，为什么不行（**失败记录最值钱**）
3. 最终怎么做的（配一张图/一段 15 秒录屏）
4. 现在的数据（截图 + 一个数字）
5. 明天要解决什么
```

| # | 发布时间 | 主题方向 | 目的 |
|---|---|---|---|
| 1 | 10/02 | 立项 + 核心机制怎么定下来的 | 立人设，让人知道这项目是活的 |
| 2 | 10/05 | 第一个灰盒原型能跑了 | 给信心，展示进展 |
| 3 | 10/09 | 垂直切片完成 + 第一次卡关 | 展示迭代能力 |
| 4 | 10/13 | 平衡过程 + 一个具体数字的取舍 | 展示技术深度 |
| 5 | 10/16 | 玩法全貌 + 试玩反馈 | 展示完成度 |
| 6 | 10/19 | 冲刺期日常 + 踩坑 | 拉互动，催试玩 |
| 7 | 10/21 上午 | 参赛 + 感谢 + 后续计划 | 收尾，承接流量 |

**排期原则**：前 3 篇拉预期，中间 2 篇证明在认真做，最后 2 篇拉互动和试玩。

## 50 试玩人数获取漏斗（最难的一条）

这是唯一一条"硬指标"，且必须在 **10/21 12:00 前**完成。所以要 10/15 就开始推。

| 渠道 | 做法 | 预估 |
|---|---|---|
| **TapTap 论坛【作品自荐】** | 每日在固定时间发帖更新进度（附可玩链接）。这类帖子在 TapTap 站内流量最直接 | 5–15 |
| **GameJam 参赛身份本身** | 参赛页会被平台推荐，评审期前有曝光 | 被动 5–10 |
| **微信/QQ 独立游戏群** | 发可玩链接（不要只发宣传图），说明是 GameJam 求反馈 | 10–20 |
| **朋友 + 同事 + 同学** | 明确说"帮我点进去玩 3 分钟"，而不是"你看看" | 5–10 |
| **小红书 / 知乎 开发日志** | 把 5 篇日志同步过去，引流到 TapTap | 5–15 |
| **Steam 页面**（如同步发） | 新品节/新品标签曝光 | 不确定 |

**关键动作**：在日志和自荐帖里放**可直接点开的可玩链接**（不是"敬请期待"），并在帖子里明确写"试玩 3 分钟就能玩完前半段，帮我留个言"。

## 合规与素材清单

- [ ] 认证开发者：个人主体即可，**无需营业执照**
- [ ] 隐私政策 + 用户协议：独立页面、链接真实可访问、**不能用论坛帖承载**
- [ ] **游戏标题在提交审核后不可自行修改**（要走工单）→ 名字要想清楚再提交
- [ ] 物料红线：不能有提现/物质奖励、不能夹带联系方式或无关广告、**不能引导好评**、不能蹭热词角标
- [ ] 宣传图不可拼接、不可随意用真人素材
- [ ] 若核心内容含 **AI 直接生成部分**（剧情/角色设定/美术资产）→ **在报名资料中备注说明**（核聚变明确要求，GameJam 建议同样主动说明）
- [ ] 截图建议 8 张：主界面 / 核心机制特写 / 成长曲线 / 离线结算 / 里程碑解锁 / 一句最有冲击力的话

## 风险清单

| 风险 | 影响 | 应对 |
|---|---|---|
| 主题公布后要求与原案冲突 | 白干 4 天 | 阶段 0 只做不依赖主题的骨架（核心循环 + 数值框架），主题层做成可替换的皮 |
| 试玩人数凑不到 50 | **直接失格**（不是扣分，是不参赛） | 10/15 起每天推，微信群提前踩点；GameJam 群 / TapTap 官方群提前加 |
| 内容量不足显得"没做完" | 影响评审印象 | 用"深度循环"代替"广度堆料"：一个系统做透 > 五个系统做浅 |
| 数值失控（后期膨胀到没法看） | 中期体验崩 | 前期就要定上限/瓶颈机制，别留到最后 |
| iOS 端过审不确定性 | 参赛只需单机包，但宣传不能承诺 iOS 上线时间 | 报名时只承诺「试玩版」，不承诺 App Store 上架日期 |
| 平衡/存档 bug 在截稿前暴露 | 手忙脚乱 | 阶段 3 强制冻结功能，只修 bug |
